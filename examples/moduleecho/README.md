# moduleecho — полный образец протокол-модуля AntiNet

Эталонный **companion-протокол-модуль** AntiNet: скачиваемый Go-артефакт (Android — `.so`
`-buildmode=c-shared`, грузится `dlopen`'ом в зарезервированный слот-процесс; Desktop — обычный
форкнутый бинарь). Это не приложение и не APK: модуль цепляется к AntiNet через локальный SOCKS5,
слушающий сокет для которого создаёт сам хост. Протокол у echo — **passthrough** (прямой проброс
трафика, без своего wire-формата), чтобы показать всю обвязку контракта чисто, без
протокол-специфики.

> **Это полный референс, а не минимальный скелет.** echo демонстрирует и обязательные части
> контракта, и все опциональные. Опциональные помечены `// DEMO` и гейтятся — копируйте как скелет
> и убирайте то, что вашему протоколу не нужно. Контракт целиком — `../../MODULE_API.md`.

## Раскладка

| Файл / каталог | Зона |
|---|---|
| `module.json` | единый дескриптор-источник: `schemes`/`name`/`description`/`helperBinary{android,desktop}`/`handoverMode`/`parallelPing`/`settings` + секция `build`. `build.py` генерирует из него dist-`module.json` для обеих платформ (§2.1). Ключей `android{service,actionActivity}` в дескрипторе нет — модуль не приложение и своей Activity не имеет |
| `native/echo/cmd/helper/main.go` | **один файл — это весь модуль**, см. ниже |
| `dist/` | билды: `dist/android/<abi>/libechohelper.so` + `dist/desktop/<os>_<arch>/echo-helper`, рядом с каждым — `module.json`. Gitignored |

### Что делает единственный файл модуля

Helper (§2.3) — это:

- **SOCKS5-фронт** на сокете, который создаёт и передаёт хост (порт известен хосту сразу, файла
  `socks.port` нет). Сам протокол SOCKS5 целиком берётся из канона `shared/socks5` (§4) — модулю
  принадлежит только транспорт: `echoUDPTransport` и дозвон по `CONNECT`.
- **protect-fd**: `SCM_RIGHTS` на Android, bind к физическому адаптеру на десктопе — один вызов
  `dialControl`.
- **Все stdout-маркеры контракта**: `PROGRESS|` (тост), `LOG|` (§2.9, постоянная запись),
  `ACTION_REQUIRED|`/`ACTION_CLOSE|` (§2.7, декларативное правило — рисует хост), `STATUS|` (§2.13,
  типизированное состояние).
- **Сабкоманды** `summarize`/`normalize`/`canping` (§2.2, §2.6, §2.10).
- **Реакция на события хоста** — `setHostEventHandler` (§2.8).
- **Off-tunnel резолвер** своих dial-таргетов: канон `shared/dns`, список серверов приходит в
  `DNS_SERVERS=`.
- **Самодекод `LINK`** из конфига, переданного содержимым, а не файлом.

**Платформенного кода и build-тегов здесь нет ни строчки**: точки входа, разговор с хостом,
жизненный цикл и protect — каноны `shared/` (§4).

⚠ Контракт восстановления echo демонстрирует через `profileDir` (consent-маркер с окном в 15 минут),
а не через блоб `STATE_SAVE|`. Пример блоба — в qWDTT.

## Поведение

- `echo://<label>[#name]` — чистый passthrough: пингуется (реальный RTT), подключается без действий.
- `echo://<label>?action=1` — на **коннекте** helper отправляет `ACTION_REQUIRED` (демонстрация
  интерактивного действия), пока включена настройка «Показывать тестовый диалог при коннекте» и нет
  свежего подтверждения (окно 15 минут, §4.2); `canping` у такой ссылки отвечает «можно» только
  внутри окна. Диалог рисует хост — Android `ModuleActionActivity`, Desktop —
  host-рендерер `antinet-action` — по декларативному правилу, которое отдаёт helper, без единой
  строчки UI-кода в модуле. Какие типы прогнать — настройка `demoTypes`; `browser` проверяет всё
  окно `webview` (§2.7) на собственной странице модуля: прокси модуля, User-Agent, заголовки, cookie
  до и после (включая HttpOnly), выход со страницы проверки, «Готово», одноразовый профиль — итог по
  каждой возможности пишется в журнал модуля, неподдержанные хостом (`hostSupports`) пропускаются
  с пометкой. На **пинге** — тост «нужно действие», а конфиг остаётся непроверенным (`-1`, не
  провал): спросить человека некого, если модуль не объявил `pingNeedsConsent`.
- Импорт `echo:мойлейбл` или `{"echo":"мойлейбл","name":"Имя"}` (вставка или файл) → сабкоманда
  `normalize` приводит это к `echo://`-ссылке.

## Как использовать скелетом

Скопируйте каталог примера рядом, под своим именем:

```bash
cp -r examples/moduleecho examples/mymod
```

1. `module.json`: `schemes`/`name`/`description`/`helperBinary`/`homepage`/`updateUrl` — под свой
   модуль. Идентичность модуля — имя каталога (`<id>` в `modules/<id>/`); package и applicationId
   переименовывать негде и незачем.
2. `native/echo` → свой Go data-plane: **замените тело `d.Dial(...)` в `handleConn`** на свой
   wire-протокол. Остальное — SOCKS5-фронт, protect, `PDEATHSIG`, сабкоманды — оставьте как есть.
   Декод своей ссылки держите в одной Go-функции, которую переиспользуют `summarize`, `normalize` и
   самодекод при коннекте.
3. Интерактивное действие (`ACTION_REQUIRED` по декларативному правилу, §2.7–2.8) нужно только если
   у вас есть шаг с UI: капча, логин, 2FA. Отправляйте его по своему условию, а не всегда; рисовать
   ничего не надо, это делает хост. Шага с UI нет — просто не отправляйте `ACTION_REQUIRED`.
4. `normalize` нужен только если ваш конфиг живёт не только как `scheme://`-ссылка, но и как JSON,
   base64 или файл.

## Сборка

```bash
python build.py --os android --module echo --abis arm64-v8a   # .so (c-shared)
python build.py --os linux   --module echo                    # desktop
python build.py --os all     --module echo                    # android + все desktop-цели
```

Детали — `../../MODULE_API.md` §5, внутренности сборщика — `../../PORTING.md`.
